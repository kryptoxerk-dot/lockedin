How the lock works.

Everything here can be checked against the open-source code and the chain. Where something depends on trust or could fail, it says so.

Overview

$LOCKEDIN is a pump.fun token with one mechanism. Half of every creator fee goes to a buyback vault. When the vault has enough, anyone can run a cycle: it buys $LOCKEDIN and moves the whole purchase to a brand-new address that has no private key. Every cycle adds one locked holder, counted on-chain.

The token launches with its fee split already set to 50% vault and 50% creator, and frozen, in the same transaction that creates it. That transaction also makes the creator's 2 SOL dev buy, so nobody can buy before it.

A cycle, step by step

  1. Fees are distributed. pump.fun holds creator fees until someone calls its public distribute instruction, which pays each half to its recipient.
  2. The vault reserves what the cycle must pay for: its own rent, rent for the new holder's token account, and a fixed 0.00005 SOL to whoever submits the cycle. What is left must be at least 0.02 SOL. One cycle spends at most 0.2% of the market's SOL reserve; anything above that waits for the next cycle.
  3. The vault buys on the bonding curve, or on the PumpSwap pool after graduation. The program derives the pool itself and checks that the buyer is the vault and the token is $LOCKEDIN.
  4. At least 65% of the budget must be spent. This stops a caller from buying a single token and making the vault pay rent for an empty lock.
  5. Everything bought moves to lock n, an address the program derives from the mint and the lock number. The caller cannot choose it.
  6. The counter goes up by one.

All of it happens in one instruction, so a purchase never sits anywhere it could be sold from. Our keeper submits cycles automatically every minute; if it ever stops, anyone can submit the same instruction.

What the program cannot do

  • Move locked tokens. No instruction transfers, withdraws or closes anything a lock address owns. The lock seed appears in exactly one instruction: the one that creates the lock and fills it.
  • Send vault SOL anywhere else. Vault SOL can only go to a pump.fun buy of $LOCKEDIN (including pump.fun's own fees on that buy), rent for the new lock's token account, and the fixed submitter fee.
  • Change. Before the token is created, the program's upgrade authority is removed and its pause admin is set to an address nobody can sign for. After that, nobody (us included) can modify, pause or redeploy it.
  • Mint or freeze tokens. pump.fun revokes the mint and freeze authorities at creation. The lock accounts have no delegate and no close authority.

What can still go wrong

  • pump.fun can change its programs; ours cannot follow. The program calls pump.fun's buy instructions in today's format. If a future pump.fun upgrade changes that format incompatibly, cycles stop for good, and SOL still arriving in the vault stays there unspent. Tokens already locked stay locked either way.
  • The creator wallet is a normal wallet. It receives the other 50% of creator fees and holds the 2 SOL dev buy. Those tokens are not locked and can be sold.
  • Buybacks are market buys. Each cycle is capped at 0.2% of the market's SOL reserve, small enough that sandwiching it costs an attacker more in fees than it makes. Buybacks still pay the market price.
  • Locking costs rent. Each lock permanently uses about 0.002 SOL of the vault's budget for its token account. Small cycles spend proportionally more on rent, which is why there is a 0.02 SOL minimum.
  • Locking is not burning. Locked tokens stay in the total supply. They just sit at addresses nobody controls.
  • No third-party audit. The code is open, has been through an internal and an independent adversarial review (findings and fixes are in docs/security.md), and is tested against mainnet's real pump.fun programs. It has not been audited by a security firm.
  • It is a memecoin. Nothing here is investment advice or a promise about price.

Verify it yourself

  1. Same code as deployed. The program is built in a pinned Docker image, so anyone can rebuild it and compare hashes. Solscan and Solana Explorer show it as a verified build of the public repository.
  2. Nobody can change it. solana program show EMs5GHLJ1MMGrvVxVQKLjpSXpmkeNfc2gXjvAVEhBr2J reports Authority: none.
  3. Nobody can pause it. The config account's admin is 11111111111111111111111111111111.
  4. The split is 50/50 and frozen. The token's pump.fun fee-sharing config lists the vault and the creator at 5,000 bps each, and can no longer be edited.
  5. Every lock is real. Lock n is the program address for ["hold", mint, n]. It is off the ed25519 curve, so it has no key. The wall lists every one with its balance.

Step-by-step commands are in docs/verify.md. The full test output is in docs/readiness.
